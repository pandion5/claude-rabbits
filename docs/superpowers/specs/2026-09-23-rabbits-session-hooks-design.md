# rabbits 세션별 런 마커와 하니스 훅 (설계 기록)

- 작성일: 2026-09-23
- 상태: 구현 완료 (0.37.0)
- 배경: 사용자 요청은 rabbits:run 과 dogs:run 의 용도를 구분하고 최신 동향을 조사해 두 플러그인을 발전시키는
  것이었다. 이 문서는 rabbits 쪽만 적는다. dogs 는 자기 리포에서 따로 구현한다.

## 조사에서 가져온 근거

- 멀티 에이전트 실패는 명세와 조율 문제가 대부분이다(MAST). 사후 감사는 사전 예방에 거의 기여하지
  못했다(arXiv 2606.14589). 규칙 위반과 부정확한 자기 보고가 실패에서 차지하는 비중이 늘고 있다
  (arXiv 2605.29442).
- 외부 신호 없는 자기 수정은 효과가 작다. 구조화한 평가 기준은 판정 편향을 줄인다(arXiv 2604.22891).
- 제품 쪽 흐름은 구현과 검증의 분리, 규칙을 문서가 아닌 코드로 강제하는 방식, 가벼운 경로의 추가다.

rabbits 에 적용한 방향은 "문서 규칙을 하니스 훅으로 옮긴다"와 "피드백에 외부 근거를 붙인다" 두 가지다.

## 용도 구분

두 질문으로 가른다. 무엇을 만들지 정해졌는가. 끝났는지를 명령이나 파일 상태로 확인할 수 있는가. 둘 다
그렇다면 dogs:run, 하나라도 아니면 rabbits:run 이다. 한두 파일 수정은 둘 다 쓰지 않는다. 두 스킬의
description 과 when_to_use 에 서로의 이름을 적고 README 에 "언제 쓰나" 절을 두었다.

## 결정

| ID | 결정 | 이유 |
|----|------|------|
| D1 | 런 마커를 `.rabbits/runs/<세션 ID>.md` 로 나눈다. 경로는 스킬 본문 치환(`${CLAUDE_SESSION_ID}`)으로 정해진다 | 같은 리포의 두 세션이 서로의 종료를 막던 문제(백로그 45) |
| D2 | 종료 가드는 자기 세션 마커만 보고, Stop 입력의 background_tasks 에 워커나 워크플로가 있으면 통과한다 | 대기 전환 개명 규약(run-waiting.md)을 없앤다. 원복 누락으로 가드가 꺼진 채 커밋까지 간 사례(백로그 33) |
| D3 | 세션 기록의 마지막 queue-operation 이 enqueue 면 통과한다 | 스모크에서 워커 완료 알림이 전달 전일 때 오차단 1회가 났다 |
| D4 | SubagentStop 결과 블록 게이트. 위임문에 계약이 있는 워커가 블록 없이 끝나면 한 번 되돌린다 | 형식 누락이 REVISE 라운드를 쓰던 문제(백로그 22) |
| D5 | SessionStart(compact, resume) 복구 훅. 런 진행 사실과 마커, 보고서, 스킬 경로를 문맥으로 넣는다 | 자동 압축 뒤 스킬은 앞 5,000토큰만 남는다 |
| D6 | self-audit 은 `--repo`, `--session` 으로 대상과 세션을 받는다. README 드리프트와 미푸시 검사는 rabbits 리포일 때만 돈다 | 다른 프로젝트 런에서 플러그인 리포를 감사하던 결함 |
| D7 | 감독 절을 현재 하니스에 맞춘다. 대화형 세션의 워커는 전부 백그라운드이고 Agent 호출에는 maxTurns 인자가 없다 | 문서가 없는 기능을 전제했다 |
| D8 | 코칭 피드백에 실패한 명령 출력이나 반증 위치를 붙인다 | 외부 신호 없는 자기 수정은 효과가 작다 |
| D9 | 훅 명령을 `sh "${CLAUDE_PLUGIN_ROOT}/hooks/<파일>"` 로 부른다 | 훅 스크립트가 git 에 실행 비트 없이(100644) 들어 있어 맥과 리눅스에서는 직접 실행이 권한 오류로 실패할 수 있다. 0.36.0 까지의 종료 가드도 같은 상태였다 |

## 계획과 달라진 점

- 단계 6 세부를 report.md 로 옮기지 않았다. QA 원장 여러 항목이 SKILL.md 의 문구를 직접 확인하고 있어
  옮기면 원장도 함께 바꿔야 한다. 압축 뒤 손실은 복구 훅과 SKILL.md 첫머리의 재독 지시가 맡는다.
- 복구 훅 문구를 명령형에서 사실 서술로 바꿨다. 공식 문서가 명령형 문구는 프롬프트 주입 방어에 걸릴 수
  있다고 안내한다. 무엇을 할지는 SKILL.md 앞부분에 적었다.
- D3 은 계획에 없었다. 스모크에서 찾았다. D9 도 계획에 없었다. 릴리스 직전 파일 모드를 보다가 찾았다.

## codex 검토 중 받아들이지 않은 것

- background_tasks 를 JSON 으로 파싱하라는 지적. 문자열 값 안의 따옴표는 이스케이프되므로
  `"type":"subagent"` 는 항목에서만 나온다.
- 사용자 답변 대기용 명시적 대기 상태. 사용자 질문은 AskUserQuestion 으로 하면 턴이 끝나지 않는다.
- 워커를 파견 때 등록하라는 지적. SubagentStart 입력에는 위임문이 없다. 위임문의 계약 유무가 판별 기준이다.
- 두 번째 게이트 실패 때 수용을 막으라는 지적. 단계 4 의 블록 누락 REVISE 가 이미 막는다.

## 검증

- 훅 입력 사례 시험. behavior-check 4사이클이 모두 통과한다. 대기열 검사를 뺀 변형은 사이클 1 에서 실패한다.
- 실세션 스모크(2.1.280, 같은 리포 대화형 세션 둘).
  - 다른 세션 런 중에도 차단 0회였다.
  - 워커 대기 중 턴 종료는 통과했고 완료 알림으로 런이 이어졌다.
  - 블록을 빼라고 지시한 워커가 게이트에 한 번 되돌려진 뒤 블록을 붙였다.
  - 압축 뒤 모델이 복구 문맥을 그대로 인용했다.
  - 워커 없이 턴을 끝내려 하자 차단됐고 사유가 AskUserQuestion 을 안내했다.
  - 대화형 `--resume` 에서는 훅이 돌고 출력도 냈지만 문맥이 모델에 붙지 않았다(2회 중 2회). `-p` 재개에서는
    붙었다. 재개 뒤에는 종료 가드가 첫 턴 종료를 막아 런을 드러낸다.
- D9 적용 뒤 `-p` 세션(세션 ID 지정, 마커 미리 생성)에서 종료 가드가 차단 1회를 기록했다. 맥과 리눅스에서는
  아직 돌려 보지 않았다.
- 0.37.1: 로컬 디렉토리 마켓플레이스 설치본은 캐시가 아니라 원본 리포를 그대로 실행한다. 설치 기록의
  installPath 는 캐시를 가리키지만 스킬 기준 경로와 `CLAUDE_PLUGIN_ROOT` 는 원본 리포였다(rabbits, dogs 둘 다).
  SKILL.md 와 README 의 "캐시 스냅샷을 실행한다" 서술을 설치 방식별로 고쳤다. 이 때문에 리포를 고치는 동안
  이미 떠 있는 세션의 훅도 새 스크립트를 실행한다. 0.36.0 스킬로 시작한 세션은 옛 마커(run-active.md)를 만들고
  새 가드는 그 마커를 보지 않으므로, 그런 세션은 다시 시작해야 가드가 걸린다.
