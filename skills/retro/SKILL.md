# rabbits retro — 런 보고서 회고 프로토콜

너는 이 회고의 **분석가**다. 이미 저장된 런 보고서만 근거로 반복 패턴을 뽑아 개선 백로그를 제안한다.

**시작 선언:** "rabbits 회고 시작 — 대상 <경로>, 최근 <N>건"

## 하드제약 (위반 시 즉시 중단)

1. **읽기 전용**: 보고서·코드·설정 일절 수정 금지. 재조사·재실행 금지 — 보고서에 적힌 것만 쓴다.
2. **백로그는 제안까지**: `.rabbits/backlog.md`에 **사용자 승낙 전 추가 금지**. 제안 목록을 출력하고
   승낙(AskUserQuestion 또는 사용자 응답)을 받은 뒤에만 추가한다.
3. **근거 없는 패턴 주장 금지**: 모든 패턴에 **보고서 파일명 2건 이상**을 인용한다. 1건짜리는
   "관측 1회"로만 적고 패턴으로 승격하지 않는다.
4. **표본 부족 중단**: 수집된 보고서가 **3건 미만이면** 분석하지 않고 "표본 부족(N건) — 런을 더
   쌓은 뒤 다시" 라고 보고하고 종료한다(억지 패턴 방지).

---

## 단계 1 — 수집

인자: $ARGUMENTS (경로·`최근 N건` 모두 선택. 미지정 시 기본 최근 **20건**)

- 경로 결정 우선순위: ①인자로 준 경로 → ②대상 리포 `.rabbits/config.md`의 `# 런 보고서 경로`
  섹션에 적힌 절대경로(집중 경로) → ③`.rabbits/reports/`.
- 집중 경로는 `<경로>/<프로젝트명>/<날짜>-<슬러그>.md` 구조이므로 **하위 폴더까지 재귀** 수집한다.
- 파일명 날짜 내림차순으로 최근 N건만 취한다. **건수·프로젝트별 분포를 나레이션**한다.
- 여기서 하드제약 4(표본 부족)를 판정한다.

## 단계 2 — 읽기

- 각 보고서를 Read해 아래를 표 1개로 집계한다: 보고서 파일명 · 프로젝트 · 워커 메타(아키타입·모델·
  라운드 수·판정) · REVISE 사유 · 미해결 항목 · 감사 발견(건수·심각도).
- 보고서 서식이 달라 항목이 없으면 `—`로 두고 넘어간다. 추측으로 채우지 않는다.
- 20건 이상이면 서브에이전트 2~3명에게 파일을 나눠 병렬 요약시키고 표만 회수해도 된다.

## 단계 3 — 패턴 추출

아래 3종을 각각 **근거 보고서 파일명 2건 이상과 함께** 뽑는다. 없으면 "해당 없음"으로 명시한다.

1. **자주 REVISE 나는 아키타입**: 아키타입별 REVISE/코칭 발생률 + 대표 사유 1줄.
2. **반복되는 미해결 유형**: 미해결 항목을 유형으로 묶고 재발 횟수 표기(예: 환경·권한·범위 누락).
3. **대장 행동 약점**: 스코프 이탈·과분할/과소분할·게이트 남용·나레이션 누락·규약 미준수 등,
   보고서 본문에 드러난 오케스트레이션 습관 문제.

## 단계 4 — 개선 백로그 제안

- 각 패턴을 **실행 가능한 1줄 작업**으로 변환해 `- [ ] 항목` 형식으로 출력한다(패턴당 1~2건,
  총 5건 이내). 각 항목 뒤에 근거 보고서 파일명을 괄호로 단다.
- 목록 출력 후 **추가 여부를 사용자에게 묻는다**. 승낙 시에만 `.rabbits/backlog.md` 말미에 추가하고
  (기존 항목 수정 금지, 추가만) 추가한 건수를 보고한다. 거절·무응답이면 목록만 남기고 종료한다.
