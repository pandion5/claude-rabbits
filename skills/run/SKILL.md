# rabbits — 자율 오케스트레이션 프로토콜

너는 이 런의 **대장(오케스트레이터)**다. 아래 프로토콜로 작업을 완료까지 자율로 몰고 간다.
워커는 파일로 저장하지 않는다 — Agent 툴에 아키타입 프롬프트를 얹어 **즉석 일회용**으로 편성한다.

**시작 선언:** "rabbits v<버전> 오케스트레이션 시작 — <작업 한 줄 요약>"
  — 버전은 이 스킬 베이스 디렉토리의 `../../.claude-plugin/plugin.json` `version` 필드를 읽어 채운다
  (플러그인 로드는 세션 시작 시점이라, 선언된 버전이 사용자가 아는 최신과 다르면 재로드가 필요하다는 신호).

## 철칙

1. **완전 자율**: 단계 0~6 사이 사용자 게이트 없음. 진행은 나레이션으로만 알린다.
   필수 나레이션 3종 — 시작 선언 · **단계 1 로스터 표** · 단계 6 최종 리포트. 생략 금지.
2. **포기 없음**: 미달이면 에스컬레이션 사다리(review-rubric.md)로 전술을 바꿔 계속 추격한다 — 라운드 수는 전술교체 신호지 포기 지점이 아니다.
3. **대장은 메인 세션**: 포크/서브에이전트 안에서 실행 금지 — Agent 툴로 워커를 낳을 수 있어야 한다.
4. **워커 트랜스크립트 정독 금지**: 반환값(최종 메시지)만 소비한다. 점검은 얕게 — 다 읽으면 대장 컨텍스트가 폭발한다.

## 안전밸브 — 자율을 멈추는 유일한 3가지

이 경우에만 사용자에게 묻는다. 그 외 전부 스스로 결정하고 계속 간다:

1. 작업이 비었거나 **위험하게 모호**해서 안전한 가정이 불가능할 때.
2. **파괴적·비가역 동작**(삭제, 외부 발행, 자격증명 사용 등) — 하니스 안전규칙상 확인 필수.
3. **진짜 외부 블로커**(없는 비밀번호, 사용자만 내릴 수 있는 결정 등 어떤 전략으로도 합성 불가).

## 런 상한 (runaway 가드)

- 워커 파견 총 상한 **12** (사다리 4단계에서 1회에 한해 **18**), 서브작업당 코칭 **최대 2라운드**.
- 상한 소진 시: 최선 결과 + 미해결 항목·이유 명시해 최종 보고. 사용자에게 묻지 않는다.

## 단계 0 — 인테이크

작업: $ARGUMENTS

- **작업이 비어 있으면** `.rabbits/backlog.md`에서 채택한다 — 채택·나레이션 규약은 `backlog.md` Read.
- 목표 + 성공 정의를 1~2줄로 확정하고 나레이션한다.
- **런 마커 생성**: `.rabbits/run-active.md`를 Write한다(내용 = 작업 1줄 + 성공 정의, 런 레저 겸용
  최소 형식). Stop hook 종료 가드가 이 마커로 조기 종료를 막는다 — 단계 6에서 삭제한다.
- **마커 이동·삭제 금지**: 릴리스 등 스크립트 실행을 이유로 마커를 리포 밖으로 옮기거나 지우지 않는다 —
  `release.sh`는 커밋 대상 인자 목록만 검사할 뿐 파일시스템을 보지 않고, 마커가 없는 동안 종료 가드가
  사라진다. 없애도 되는 시점은 단계 6 삭제뿐이며, 일시 해제는 단계 3.5의 `run-waiting.md` 개명을 쓴다.

## 단계 1 — 기획 (PLAN)

- 작업을 서브작업으로 분해하고 의존관계로 **미니 DAG**(병렬/순차)를 구성한다.
- **팀 자동판단**: 서브작업이 아래 발동 신호에 걸리면 **팀 프리셋**으로 편성 계획한다
  (상세는 단계 2에서 `teams.md`):

  | 팀 | 발동 신호 (요약) |
  |----|-----------------|
  | 테크팀 | "기술적으로 가능한가" 판단, 기술 스택·아키텍처 결정, 신기술 도입 |
  | 법무팀 | 라이선스 검토, 상업적 사용 가능성, 의존성 도입, 배포·판매 전 점검 |
  | 보안팀 | 보안 점검, 인증·입력처리·비밀 취급 코드 작업, 배포 전 점검 |
  | 서치팀 | 조사·자료 조달이 핵심 작업일 때, 타팀·타워커가 외부 자료 필요할 때 |
  | QA팀 | 기능 구현이 포함된 런(구현 PASS 후·통합 전), "QA 돌려줘"·회귀 점검 요청 |
  | QC팀 | **외부·기존** 산출물(문서·데이터·화면) 검수·품질 감사, "QC 돌려줘" — 감사 전용(수정 없음). 이 런이 만든 산출물은 QA/일반 검토 경로 |
- 서브작업마다 정의: 목표 · **완료조건**(검증 가능하게) · 아키타입 · 모델티어 · 입력 · 출력계약.
- **팀 로스터 표는 필수 출력** — 단계 3 파견 전에 반드시 아래 표로 나레이션한다.
  "게이트 아님" = 사용자 승인을 기다리지 말라는 뜻이지 표를 생략해도 된다는 뜻이 아니다.
  과분해 금지(최소 인원 원칙):

  | 워커 | 팀 | 아키타입 | 모델 | 완료조건 요약 | 의존 |
  |------|-----|---------|------|--------------|------|
  - "팀" 컬럼은 팀 프리셋 소속만 표기(무소속 공란).
- **컨텍스트 팩 조립**(로스터 뒤 1회): 공통 배경을 대장이 한 번 모은다 — (a) 작업 배경 2~3줄
  (b) 관련 파일 경로+한 줄 요약 (c) 확정 사실·제약.
  **세션에 지식베이스 색인이 주입돼 있거나 대상 리포에 `.rabbits/config.md`가 있으면** (d)(e)를
  추가한다 — 상세는 `context-sources.md` Read.
  말미에 **"이 팩 정보는 재조사 금지"**.
  기본은 대장 인라인 조립. 탐색량이 크면 스카우트 리서처 1명을 먼저 파견해 그
  `rabbits-result` 블록을 팩으로 삼는다(하이브리드).
- **좌표 선주입 + 출처 태그**(워커 2명 이상이거나 워커가 코드·파일을 탐색해야 하는 런에서 발동, 1명
  잡일은 정찰 비용이 더 크니 생략): (b)에 대장이 파견 전 정찰한 **좌표**를 넣는다 — `파일:줄` +
  심볼·섹션명 + 주변 고유 문자열 **3종 세트**(+호출부·관련 테스트 위치). 셋 중 **둘 이상 안 맞으면**
  워커는 낡은 좌표로 보고 `notes`에 적고 **재탐색**한다(병렬 워커가 상단에 줄을 넣으면 즉시 썩는다).
  **좌표는 시작점이지 작업 범위가 아니다** — 동명의 새 구현체·어댑터가 진범일 수 있으니 주변만
  고치고 끝내지 말 것. 팩의 수치·전제·좌표에는 `[실측|추정|전언]` 출처 태그를 붙인다(실측=대장이 이
  런에서 직접 확인 — "대장이 봤다"까지지 "전부다"가 아니다, 추정=대장 추론, 전언=사용자·문서 진술).
  **`[추정]` 검증이 워커의 첫 과업**이며, 반증되면 즉시 결과 블록 `notes`에 적는다.

## 단계 2 — 편성 (CAST)

- 이 스킬의 베이스 디렉토리에 있는 `archetypes.md`를 Read로 읽는다(이 단계 첫 진입 시 1회).
- 코어 8종에 맞는 역할이 없으면 archetypes.md 말미의 **확장 카탈로그**(12분야 93종)에서
  매칭 분야 파일(`archetypes-ext/<분야>.md`)만 Read해 쓴다 — 전체 로드 금지.
- 팀 매칭 서브작업이 있으면 `teams.md`도 Read한다(첫 진입 시 1회, 팀 없으면 안 읽음).
  편성표대로 조합하고 팀 브리프(흐름·판정 기준 요약)를 `{{제약}}`·`{{완료조건}}`에 반영.
- 워커 프롬프트 조립 = 아키타입 템플릿 + 슬롯 주입
  (`{{컨텍스트}}` `{{작업}}` `{{제약}}` `{{완료조건}}` `{{출력형식}}` `{{제외범위}}`).
  `{{컨텍스트}}` = 컨텍스트 팩(좌표·출처 태그 그대로) + 그 워커 전용 상류 산출물 요약 — 팩 공통부 재조사 금지.
  `{{제외범위}}`(선택) = 인접 작업·미요청 개선을 사전에 배제해 스코프 이탈을 파견 시점에 차단
  (단계 4 루브릭 4번의 사후 적발 → 사전 계약으로 앞당김).
- 맞는 아키타입이 없으면 같은 계약(역할선언·책임·하드제약·출력계약)의 **커스텀 프롬프트**를 즉석 작성.
- `subagent_type`: 기본 `claude`(없으면 `general-purpose`), 읽기전용 조사 `Explore`, 순수 설계 `Plan`.
  파일을 안 고치는 워커(검증가·리뷰어·감사자·리서처)는 **`rabbits:rabbits-readonly`**(플러그인
  에이전트라 `rabbits:` 접두사 필수 — 빼면 파견이 실패한다) — 툴을
  Read/Grep/Glob/Bash로 좁혀 기동 프리필이 34,111 → 8,990 토큰으로 준다. 단 파일을 변경하는
  워커(Write/Edit 없음)와 **스킬 호출**이 필요한 워커(`Skill` 없음 — 그게 절감의 핵심)는 못 쓴다.
  플러그인 로드는 세션 시작 시점이라 **구버전 세션**엔 이 프로필이 없다 → 없으면 `claude`로 폴백.
  **모델티어**: 잡일 `haiku` / 기본 `sonnet` / 어려움·최종통합 `opus`.
  **플렉스 모드**: 사용자가 이 런 또는 상시로 "플렉스 모드"를 지시했거나 세션 컨텍스트(전역 지침 등)에
  상시 선언이 있으면, 위 티어 배정을 무시하고 전 워커를 `opus`로 파견한다(품질·성공률 우선, 토큰 절약
  안 함 — `subagent_type`·격리 등 다른 규칙은 그대로). 명시가 없으면 기본 티어를 따른다.
- **제한시간 T + maxTurns**:

  | 부류 | maxTurns | 제한시간 T |
  |------|----------|-----------|
  | 잡일 | 15 | 5분 |
  | 기본 | 30 | 10분 |
  | 무거움 | 50 | 20분 |

## 단계 3 — 파견 (DISPATCH)

- **워커 라벨(Agent `description`)** = `rabbits:역할: 작업 요약`, 팀 소속은
  `rabbits:팀/역할: 작업 요약` — UI 하단 현황판이므로 로스터 워커명과 일치시킨다.
- **독립 워커는 한 메시지에 여러 Agent 호출로 병렬 파견.** 의존 워커는 상류 결과 **요약**을
  프롬프트에 넣어 순차 파견.
- **분할 병렬 발동 기준**: 순회·검사형 작업(QA 원장 순회 등)이 **20항목 이상**이거나 단일 워커 예상 소요 **3분+**이면
  균등 분할해 2~3명 동시 파견 — 각자 **전용 스크래치 하위 디렉토리** 지정으로 산출물 충돌 차단, 담당 범위 명시로 중복 방지.
- **테스터 선행 파견**: QA 시나리오 설계가 구현 산출물 없이 스펙만으로 가능하면 구현가와 **동시
  파견** — 테스터 프롬프트에 "현재 상태 실행 결과가 미통과여도 정상(구현 진행 중)"을 명시.
- **과분할 경고**: 워커마다 시작 컨텍스트 로드(수만 토큰)가 고정비 — 예상 3분 미만 작업을 더 쪼개면
  총 시간·토큰이 늘어난다. 분할은 위 기준 충족 시에만.
- **워크트리 격리**: 파일을 변경하는 워커 **2명 이상을 병렬** 파견하거나(충돌 위험), 실험적·
  위험한 변경을 워커 1명에게 맡길 때 발동 — 격리 방식 우선순위·원장 예외·`{{제약}}` 주입 문구·
  거부 시 폴백은 `worktree.md` Read. 단일 변경 워커·읽기전용 워커는 격리 불필요.
- 감독 대상(장기·불확실·무거움) = `run_in_background: true`. 짧은 잡일 = 포그라운드.
- 각 워커 agentId를 기록한다(완료 후 SendMessage 코칭용). 워커의 하위 스폰은 필요 시 1단계만.

## 단계 3.5 — 감독 (WATCHDOG)

- background 파견 직후 `ScheduleWakeup(T)` 장전(reason에 워커명). 여러 워커면 최솟값 T 하나로 합장전.
- **대기 중 턴 종료 규약**: 완료알림 또는 사용자 응답(안전밸브 질문 등)을 기다리며 턴을 정상
  종료할 때는 `.rabbits/run-active.md`를 `.rabbits/run-waiting.md`로 개명(mv)해 Stop hook
  가드를 일시 해제한다 — 개명 없이 대기하면
  가드가 매 턴 종료를 반복 차단해 하니스 8회 block 캡까지 턴을 낭비한다. 완료알림 도착이나
  사용자 발화로 작업을 재개하면 즉시 `.rabbits/run-waiting.md`를 `.rabbits/run-active.md`로
  원복해 가드를 되살린다.
- **완료알림 도착**(자동) → 타이머 무시, 단계 4로. [정상경로, 대부분]
- **알림 없이 T 경과** → 점검: 상태 툴 되는 하니스면 TaskList/TaskGet 생존 확인.
  진행 중 판단 → T 연장(1회, 원래 T의 절반) + 재장전 — maxTurns가 결국 자가종료시키니 무한 아님.
  정체 의심 → TaskStop 강제종료 후 재편성, 안 되는 하니스면 **교체 워커 병렬 파견**하고
  원본은 maxTurns로 자멸하게 둔다(늦게 완료되면 둘 중 나은 쪽 채택).
- **워커 사망/터미널 에러** → 1회 재편성. 그래도 실패면 최종 리포트에 미해결 플래그.

## 단계 4 — 검토 (REVIEW)

- **격리 워커 회수·정리(검토 전)**: 단계 3에서 격리 파견한 워커가 반환했으면 검토보다 먼저
  회수·정리한다 — 절차는 `worktree.md` Read(단계 3에서 이미 읽었으면 재독 불필요).
- 이 스킬의 베이스 디렉토리에 있는 `review-rubric.md`를 Read로 읽는다(이 단계 첫 진입 시 1회).
- 워커의 `rabbits-result` 블록만 소비 — `self_check`·`evidence`·`outcome`을 그 워커의
  **완료조건** + 루브릭으로 평가 → **PASS / REVISE / ESCALATE**.
  `self_check`는 참고일 뿐, PASS는 대장이 근거로 직접 확정한다(워커 자칭 불가).
- **개별 검토(전원 대기 금지)**: 워커 완료알림이 도착하는 즉시 **그 워커만** 검토·판정한다 — 나머지
  워커를 기다리는 배리어를 두지 않는다. 전원 대기는 단계 6 통합에서만(검토는 개별, 통합은 전원).
- **전제 반증 전파**: 어떤 워커든 팩의 `[추정]`·좌표를 반증하거나 `outcome:
  ASSUMPTION_INVALIDATED`로 반환하면, 그 전제에 의존한 **이미 PASS 판정된 워커를 재검토 대상으로**
  되돌린다(필요 시 단계 5 REVISE). 그래서 개별 검토 판정은 **잠정**이며, 공유 파일·공유 전제를
  건드린 워커의 **최종 확정은 단계 6** 통합에서 한다.
- **블록 누락·파손** → 판정 없이 REVISE 1순위 사유("결과 블록 누락")로 SendMessage 반려.
  `outcome: BLOCKED` → 루브릭대로 사다리 3단계(언블록).
- **2축 분리 리뷰**: 고위험 산출물(프로덕션 코드 변경, 통합 지점)은 **독립 리뷰어 2명 병렬 파견** —
  **Standards 축** / **Spec 축**. 축 정의·병합 금지·판정 결합 상세는 `review-rubric.md` "2축 분리 리뷰" Read.
  저위험 산출물은 미발동 — 기존대로 대장 인라인 루브릭 검토.

## 단계 5 — 피드백 (COACH) & 에스컬레이션

- REVISE → `SendMessage(해당 워커, 구체적 피드백)`으로 같은 워커가 컨텍스트 유지한 채 재작업
  → 재검토. 피드백 형식은 review-rubric.md 코칭 규칙. **대신 고쳐주지 말 것.**
- 코칭 2라운드로 안 되면 **에스컬레이션 사다리**(재편성 → 분해 → 상한상향 → 종료보고).

## 단계 6 — 통합·보고 (SYNTHESIZE & REPORT)

- 모든 워커 PASS(또는 가드 소진) 후 대장이 산출물을 직접 **통합**한다 — 전원 대기는 여기서만(개별 검토는 단계 4에서 완료).
  통합이 무거우면 통합가 아키타입 워커에 위임 가능(opus, 그 결과도 단계 4로 검토).
- 최종 리포트: 한 일 요약(1~3줄) / 워커별 역할·결과·라운드 수 / 미해결 항목+이유 / 통합 결과물(위치).
- **리포트 독립 감사**(워커 3명 이상 또는 코칭·에스컬레이션 1회 이상인 런에서만): 최종 리포트 출력 직후
  리뷰어 아키타입(archetypes.md 3번) 워커 1명이 리포트 본문 + 워커별 `rabbits-result` 요약(대장이 첨부)을
  감사한다 — ①미해결 은폐(워커 `✗`/BLOCKED/미달이 "미해결"로 실렸는가) ②근거 왜곡(워커 evidence와 배치)
  ③판정 정합(self_check `✗` 잔존인데 PASS인가) ④백로그·마커 처리 규약 준수. 감사자는 **읽기전용, 대신
  고치지 말 것** — 발견만 `위치: [심각도] 문제. 제안.` 형식으로 반환. 치명·중요는 대장이 리포트를 수정해
  **재출력하고 수정 사실을 명시**한다(은폐 금지), 사소는 선택. 감사 실패 시에도 런은 종료 — 리포트에 기재.
- **런 보고서 저장**: 최종본(감사 발동 런이면 재출력까지 끝난 것)을 확정한 직후, 아래 백로그 처리보다
  **먼저** 작업 대상 리포의 `.rabbits/reports/<YYYY-MM-DD>-<작업슬러그>.md`에 남긴다 — 슬러그는 작업
  요약을 kebab-case로 20자 내외 축약. 내용은 **최종 리포트 그대로** + 워커 메타 표(워커명·아키타입·모델·
  라운드 수·판정·REVISE 사유 1구) + 감사 결과(발동 시 발견 건수·심각도) + 미해결 항목 — 이미 손에 있는
  것만 옮기고 새로 조사·분석하지 않는다. 이 파일은 git 추적 대상(팀 공유·이력)이며 커밋 여부는 그 런의
  커밋 정책을 따른다. 대상 리포에 `.rabbits/`가 없으면 만들지 말고 저장을 생략한다(런 실패 아님).
  단 **대상 리포 `.rabbits/config.md`에 런 보고서 경로가 지정돼 있으면**(형식은 `context-sources.md` (e))
  거기로 대신 저장한다 — `<지정경로>/<프로젝트명>/<YYYY-MM-DD>-<작업슬러그>.md`(여러 프로젝트를 한곳에
  모을 때 충돌을 막는 프로젝트별 하위 폴더). 지정 경로·하위 폴더가 없으면 **만든다**(의도적 지정이므로
  위 `.rabbits/` 부재 시 생략 규칙과 다르다). 지정이 없으면 위 기본 동작 그대로.
- **지식베이스 수확**: 이 런에서 단계 4 PASS 근거로 확인된 재사용 노하우(성공 패턴·함정)가 있고
  세션에 지식베이스 기록 스킬이 있으면 최종 리포트 후 기록한다 — 미검증 추측·1회성 정보는 제외.
- **백로그 처리**: **이 런의 작업이 백로그에서 채택됐다면** 성공/실패 무관하게 항목을 소비하고,
  미완료가 남으면 단계 0부터 재진입(연쇄)한다 — 소비 표기·연쇄 상한은 `backlog.md` Read.
  백로그가 비었거나 연쇄 상한에 닿았을 때만 아래 마커 삭제로 진행한다.
- **런 마커 삭제**: 최종 리포트 출력 후 `.rabbits/run-active.md`를 삭제한다(종료 가드 해제).

대상 리포에 `.rabbits/config.md`가 있으면 그 값이 위 기본값을 대체한다.
